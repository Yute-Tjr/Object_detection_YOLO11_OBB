# 端子检测 Web 界面与运行稳定性改进设计

## 1. 背景与目标

现有 React + FastAPI + PostgreSQL + 单 GPU Worker 已经打通上传、检测、结果展示和历史查询闭环。本轮不重构技术栈，目标是在现有架构内完成以下改进：

1. 页面在宽屏和窄屏下自适应，不再受固定内容宽度限制。
2. 检测前后对比完整展示纵向端子图片，标注文字不遮挡目标主体。
3. 上传前填写操作员、任务名称和备注，其中操作员为必填项。
4. 任务列表使用明确的“预览”按钮，并隐藏内部存储标识。
5. 修复数据库连接耗尽造成的 `503 Service Unavailable` 和历史记录暂时消失问题。
6. 为常用按钮增加克制、清晰的交互反馈。
7. Worker 输出足够定位任务进度的精简日志。

第一版继续面向单用户、单 Worker 的生产线部署场景，不引入 WebSocket、Redis、Celery、账户系统或复杂动画。

## 2. 已验证事实

### 2.1 对比图并未被后端裁剪

抽查任务 `e1eab478-7312-4ffb-8fde-7db93f007c88` 的原图与结果图，两者均为完整的 `405 × 1548` 纵向图片。当前只显示上半部分是前端对比容器固定高度和溢出裁剪造成的，不需要修改推理裁剪流程。

### 2.2 历史记录没有被删除

发生 503 时，PostgreSQL 中存在 15 个长期处于 `idle in transaction` 状态的连接，数量等于当前 SQLAlchemy 连接池容量上限。新请求无法取得连接后，任务列表和任务详情接口返回 503。数据库中的任务和图片记录仍然存在。

因此，本轮需要同时修复数据库会话生命周期和前端失败状态处理。单纯重启 API 只能临时释放连接，不能作为最终解决方案。

## 3. 保留的系统架构

```text
浏览器 React/Vite
       |
       | HTTP/JSON + 图片资源 + 短轮询
       v
FastAPI API -------- PostgreSQL
       |                  |
       |                  v
       |            持久化任务队列
       v                  |
持久化图片目录 <---- 单 GPU Worker
```

- API 负责参数校验、持久化和查询，不执行模型推理。
- Worker 串行领取任务并逐图处理。
- 前端只在任务运行时轮询，终态立即停止。
- 历史原图和结果图继续保存在服务器持久化目录中。

## 4. 页面布局与响应式设计

### 4.1 主体宽度

- 去除当前主内容区域的 `1480px` 最大宽度限制。
- 侧边栏保持固定宽度，右侧内容区域占满剩余可用宽度。
- 页面内边距使用响应式值，在大屏保留适当留白，在较窄窗口缩小边距。
- 数据表格在空间不足时允许横向滚动，不通过压缩字号隐藏字段。

### 4.2 上传与任务信息区

上传区增加三个字段：

| 字段 | 规则 |
| --- | --- |
| 操作员 | 必填；去除首尾空白后不能为空；每次新建任务都重新填写，不保存上次输入 |
| 任务名称 | 选填 |
| 备注 | 选填，多行文本 |

操作员同时由前端和 API 校验。任务创建成功后，三个字段与已选图片一起清空；任务创建失败时保留输入，方便用户修改后重试。

在宽屏下，任务信息与图片选择区域采用紧凑网格布局；在窄屏下按操作员、任务名称、备注、图片操作的顺序纵向排列。

### 4.3 检测结果对比

- 图片按自身宽高比完整显示，不再使用固定高度和 `overflow: hidden` 裁剪。
- 图片最大显示高度受视口高度约束，但必须使用 `object-fit: contain` 保留完整内容。
- 桌面端原图和结果图左右并排；空间不足时上下排列。
- 图片信息和上一张/下一张控制保持在对比卡片内。

### 4.4 常用按钮反馈

为“选择图片”“开始检测”“搜索”“刷新”“预览”统一增加：

- 鼠标悬停时背景色或边框色轻微变化；
- 短时颜色和位移过渡；
- 按下状态；
- 清晰的键盘焦点轮廓；
- 禁用状态不触发悬停效果。

不增加弹跳、缩放等影响生产操作稳定感的动画。

## 5. 任务表与历史交互

### 5.1 任务列表

- 任务 ID 改为普通文本，不再作为打开结果的隐式入口。
- 表格末列增加带图标和文字的“预览”按钮。
- 展开行继续显示任务详情，但移除内部“存储标识”。
- 详情展示任务名称、操作员、备注和必要的时间信息。
- 预览按钮在检测任务页和历史页具有一致行为。

### 5.2 请求失败时的数据保留

- 刷新任务列表失败时保留屏幕上最后一次成功加载的数据。
- 刷新当前任务详情失败时保留当前结果图和选中图片。
- 页面显示非阻塞错误提示、重试入口和服务状态，不将已有历史记录替换为空列表。
- 连续失败时降低请求频率；恢复后自动刷新为最新数据。

这项前端保护只能避免误导用户，数据库连接泄漏仍必须从后端根治。

## 6. 数据模型与 API

### 6.1 数据库迁移

`inspection_tasks` 新增 `operator` 字段。

为了兼容已经存在的历史记录，数据库字段允许为 `NULL`；所有新建任务则由 API 强制要求非空。旧任务在页面中显示 `-`，不伪造操作员。

### 6.2 创建任务接口

创建任务表单包含：

```text
files: 1-100 张图片
operator: 必填字符串
name: 可选字符串
note: 可选字符串
```

校验失败返回明确的 4xx 错误，不创建任务目录、不写入任务记录。任务查询响应增加 `operator` 字段。

## 7. 503 根因修复与连接管理

### 7.1 会话生命周期

- 将请求级数据库会话改为能够可靠执行清理的依赖形式。
- 每次请求成功后提交或结束读取事务；发生异常时执行回滚；无论成功失败都关闭会话并归还连接。
- 不允许响应返回后仍保留未结束事务。
- 为数据库异常增加结构化服务端日志，记录接口、异常类型和必要上下文，不返回内部堆栈给前端。

### 7.2 防御性配置

- 为连接池设置有限等待时间，连接不可用时快速失败并留下明确日志。
- 保留合理的连接池大小，不用盲目扩大连接池掩盖泄漏。
- 运行中任务轮询维持现有短轮询策略，但终态立即停止；连续请求失败时退避。

### 7.3 验证标准

- 连续和并发调用任务列表、详情接口后，数据库连接能够回到池中。
- 不再持续增长 `idle in transaction` 会话。
- 单个接口异常不会导致后续所有历史查询失效。

## 8. 结果图标签布局

后端渲染检测结果时，标签位置遵循以下规则：

1. 优先放在旋转框外接矩形右侧，并与框垂直方向对齐。
2. 右侧空间不足时放到框左侧。
3. 最终坐标限制在图像边界内。
4. 标签底色继续沿用框颜色语义：OK 为绿色、NG 为红色、不支持分类为灰色。

这只改变可视化结果图的文字布局，不改变检测坐标、分类输入或预测结果。

## 9. Worker 精简日志

Worker 只输出运行和排障所需信息：

```text
INFO  模型加载完成
INFO  开始任务 task_id=... images=20
INFO  [3/20] 目标检测 filename=...
INFO  [3/20] 异常分类 filename=...
INFO  [3/20] 完成 result=OK
ERROR [4/20] 失败 error=...
INFO  任务完成 task_id=... succeeded=19 failed=1 elapsed=...
```

- 不逐条输出检测框、分类分数或数据库细节。
- 正常日志不输出完整绝对文件路径。
- 发生异常时保留错误信息和必要堆栈。
- 日志格式包含时间、级别和消息，便于服务器终端直接查看。

## 10. 测试与验收

### 10.1 后端自动化测试

- 新任务缺少或只包含空白操作员时被拒绝。
- 合法操作员、任务名称和备注能够写入并查询。
- 旧任务的空操作员可以正常读取。
- 请求成功和失败后数据库连接均被释放。
- 并发查询不会耗尽连接池或留下长期空闲事务。
- 标签优先放在框右侧，越界时正确回退并限制在图像范围内。
- Worker 在开始、阶段切换、单图失败和任务结束时输出精简日志。

### 10.2 前端自动化测试

- 未填写操作员时“开始检测”不可提交，并显示校验信息。
- 操作员不会在新任务或刷新后自动恢复为上一次输入。
- 任务 ID 不再可点击，每行存在“预览”按钮。
- 任务详情不展示存储标识，并正确展示操作员。
- 列表或详情刷新失败时保留已有内容。
- 按钮具备 hover、active、focus-visible 和 disabled 状态。

### 10.3 浏览器验收

在至少三种视口下验证：

- 宽屏桌面：主内容填满可用区域，无异常大片空白。
- 常规桌面：上传、任务表和对比图信息完整。
- 窄窗口：表单和对比图正确换行，任务表可横向滚动。

使用真实纵向端子图片完成一次上传、检测、结果预览、历史页重开流程，确认图片完整、文字不遮挡主体、历史记录在 API 短暂失败后仍保留。

## 11. 非目标

本轮不包含：

- 记住上一次操作员；
- 用户账户和权限；
- 多 Worker 并发调度；
- WebSocket 推送；
- 历史记录删除或自动清理；
- 在线编辑检测框；
- 更换或重新训练模型；
- 复杂动画和主题系统。
