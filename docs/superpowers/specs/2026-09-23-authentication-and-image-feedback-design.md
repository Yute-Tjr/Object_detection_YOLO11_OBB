# 用户认证与图片结果反馈设计

日期：2026-09-23

## 1. 背景与目标

当前端子检测网页无认证机制，所有访问者都可创建任务、查看历史图片和删除任务。系统也无法把人工复核结果持久化，不利于后续分析错误和优化模型。

本次调整的目标是：

1. 新增无注册入口的登录页，只允许管理员通过命令行创建和管理用户。
2. 使用可立即撤销的服务端数据库会话，保护任务、图片、文件和反馈接口。
3. 允许登录用户对每张已完成图片中的实际检测区域提交 `OK/NG` 反馈，并记录 label1 的人工颜色。
4. 允许用户从当前未检测到的逻辑区域中选择真实的漏检区域。
5. 让不同用户的反馈互不覆盖，同一用户可修改自己对同一图片的最终反馈。
6. 保护已产生人工反馈的任务，防止其被网页删除。

## 2. 非目标

- 不提供网页注册、找回密码、修改密码或用户管理页。
- 不引入管理员、操作员等角色和权限层级；所有启用用户拥有相同的业务权限。
- 不提供检测框编辑、新建检测框或假阳性框删除工具。
- 不将漏检区域当作异常分类输入；漏检没有裁剪区域，只作为独立的目标检测错误记录。
- 不修改目标检测、异常分类、颜色分类或结果图渲染流程。
- 不在本次实现反馈数据导出和自动重训练。

## 3. 总体架构

采用数据库服务端会话，不使用 JWT 或 Nginx Basic Auth。用户登录成功后，API 生成高强度随机令牌，浏览器仅通过 `HttpOnly` Cookie 保存原始令牌，数据库只保存令牌的 SHA-256 摘要。

每次受保护请求都会校验：

1. Cookie 是否存在。
2. 会话是否存在且未过期。
3. 关联用户是否仍处于启用状态。

这使得退出登录、禁用用户和删除会话都能立即生效。API 进程负责认证，Worker 继续直接通过数据库处理任务，不需要浏览器会话。

## 4. 数据库设计

### 4.1 `users`

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `id` | UUID 主键 | 用户标识 |
| `username` | 非空、唯一、1–64 个字符 | 登录名 |
| `password_hash` | 非空 | Argon2id 密码哈希 |
| `is_active` | 非空，默认 `true` | 禁用或启用用户 |
| `created_at` | 带时区 | 创建时间 |
| `updated_at` | 带时区 | 密码或状态更新时间 |

用户名去除首尾空白后保存，禁止任何空白和控制字符；清理后必须保留至少一个字符。用户名比较严格区分大小写，`Admin` 与 `admin` 是两个不同用户，登录时不进行小写化。

### 4.2 `user_sessions`

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `id` | UUID 主键 | 会话标识 |
| `user_id` | 外键，级联删除 | 所属用户 |
| `token_hash` | 非空、唯一 | 随机 Cookie 令牌的 SHA-256 摘要 |
| `expires_at` | 带时区、非空 | 12 小时绝对过期时间 |
| `created_at` | 带时区 | 登录时间 |

会话不滑动续期。退出时删除当前会话，禁用用户时删除该用户的全部会话。遇到过期会话时执行惰性清理。

### 4.3 `image_feedbacks`

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `id` | UUID 主键 | 一次图片反馈 |
| `image_id` | 外键，级联删除 | 关联的检测图片 |
| `user_id` | 外键，限制删除 | 提交用户 |
| `created_at` | 带时区 | 首次提交时间 |
| `updated_at` | 带时区 | 最后修改时间 |

`(user_id, image_id)` 建立唯一约束。同一用户重新提交时更新该记录，不创建多个版本；不同用户的反馈相互独立。

### 4.4 `image_feedback_items`

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `id` | UUID 主键 | 区域反馈标识 |
| `feedback_id` | 外键，级联删除 | 所属图片反馈 |
| `detection_id` | 外键，非空 | 关联模型实际检测框 |
| `region_label` | 非空 | 提交时的原始模型标签快照 |
| `verdict` | `OK` 或 `NG` | 人工异常判定 |
| `color` | 可空 | label1 为 `B/G/R/W`，其他区域为空 |

`(feedback_id, detection_id)` 建立唯一约束。提交时必须覆盖图片当前的每一条 `detections` 记录。如果同一逻辑区域出现多个检测框，弹窗按检测实例分别显示和收集反馈。

### 4.5 `image_feedback_misses`

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `id` | UUID 主键 | 漏检反馈标识 |
| `feedback_id` | 外键，级联删除 | 所属图片反馈 |
| `logical_region` | `label1` 至 `label6` | 人工确认的漏检逻辑区域 |

`(feedback_id, logical_region)` 建立唯一约束。服务端把 `label1_thin` 和 `label1_thick` 都映射为逻辑区域 `label1`，其他标签保持 `label2`–`label6`。只能选择当前图片尚未检测到的逻辑区域，已检测区域不能同时标记为漏检。

## 5. 密码与会话安全

- 密码使用 Argon2id 哈希，数据库不存储明文密码或可逆密文。
- 管理脚本要求密码至少 12 个字符，通过终端隐藏输入并二次确认，不接受命令行明文密码参数。
- 对不存在的用户也执行固定的哈希验证路径，登录失败统一返回“用户名或密码错误”。
- Cookie 名称固定为 `terminal_session`，设置 `HttpOnly`、`SameSite=Strict` 和 `Path=/`。
- `SESSION_COOKIE_SECURE` 默认为 `false`，保持当前 HTTP 本机/内网部署可用；切换 HTTPS 后必须设为 `true`。
- 对 `POST`、`PUT`、`PATCH` 和 `DELETE` 请求校验 `Origin` 与当前主机一致，与 `SameSite=Strict` 共同防止跨站请求伪造。
- 会话固定 12 小时后过期，请求不延长过期时间。

## 6. 认证接口与权限边界

### 6.1 公开接口

- `GET /api/v1/health`：保持 Docker 和运维健康检查可用。
- `POST /api/v1/auth/login`：验证用户名和密码，创建会话 Cookie。
- `POST /api/v1/auth/logout`：有 Cookie 时删除当前会话，无 Cookie 时仍幂等清除浏览器 Cookie。

### 6.2 受保护接口

- `GET /api/v1/auth/me`。
- 所有任务创建、列表、详情和删除接口。
- 所有图片详情、原图、结果图和重试接口。
- 所有反馈读写接口。

未登录、会话过期或用户已禁用时统一返回 HTTP `401`。已登录但请求数据不合法时使用 `400/409/422`，不把数据校验错误伪装成权限错误。

## 7. 反馈接口

### 7.1 读取反馈

`GET /api/v1/images/{image_id}/feedback`

返回：

- 图片 ID、文件名和完成状态。
- 实际检测框列表，包含 `detection_id`、原始区域标签、逻辑区域和模型当前分类结果。
- 当前未检测到的逻辑区域候选集。
- 当前登录用户已有的区域反馈和漏检反馈；没有时返回空集。

该接口不返回其他用户的反馈。

### 7.2 创建或更新反馈

`PUT /api/v1/images/{image_id}/feedback`

请求体包含：

- `items`：每个实际检测框的 `detectionId`、`verdict` 和可选 `color`。
- `missedRegions`：用户确认的漏检逻辑区域列表。

服务端在单个数据库事务中校验并更新反馈：

1. 图片必须处理完成且不是失败图片。
2. `items` 的 detection ID 集合必须与该图片当前检测记录完全一致，不能缺少、重复或引用其他图片。
3. `verdict` 只能为 `OK` 或 `NG`。
4. `label1_thin` 和 `label1_thick` 必须提交 `B/G/R/W` 之一，其他标签禁止提交颜色。
5. `missedRegions` 只能是当前未检测到的 `label1`–`label6` 子集。
6. 无任何检测框时，至少选择一个漏检区域，禁止提交空反馈。

验证通过后，按 `(user_id, image_id)` 更新主记录，并用本次请求的区域和漏检集合原子替换原有子记录。

## 8. 任务删除保护

任务列表和详情响应增加 `hasFeedback` 布尔字段，它表示任务下任意图片是否存在任意用户反馈。

- `hasFeedback=true` 时，前端禁用删除按钮，并显示“包含人工反馈，已作为模型优化数据保留”。
- 后端删除任务前独立查询反馈是否存在；存在时返回 HTTP `409`，防止绕过前端。
- 无反馈任务继续使用现有永久删除流程。

## 9. 管理员用户工具

新增 `scripts/manage_users.py`，连接项目现有 PostgreSQL，支持：

```bash
python scripts/manage_users.py add USERNAME
python scripts/manage_users.py list
python scripts/manage_users.py reset-password USERNAME
python scripts/manage_users.py disable USERNAME
python scripts/manage_users.py enable USERNAME
```

`add` 和 `reset-password` 通过 `getpass` 隐藏输入并二次确认，禁止传入明文密码参数。`disable` 同时删除该用户的全部会话。`list` 只显示用户名、启用状态和时间，不显示密码哈希或会话令牌摘要。

Docker 部署通过以下命令创建首个用户：

```bash
docker compose exec api python scripts/manage_users.py add USERNAME
```

uv 与 Conda 原生环境使用同一脚本。网页不提供注册入口。

## 10. 前端交互

### 10.1 登录页与路由保护

- 新增 `/login` 页面，只显示用户名、密码、登录按钮和错误提示，沿用现有简约工业风格。
- 应用启动时先请求 `/auth/me`。未登录时进入登录页，已登录时进入原目标路由。
- 任意业务 API 返回 `401` 时，统一清除前端用户状态并跳转登录页。
- 侧边栏底部显示当前用户名和“退出登录”。
- 登录页不显示注册、找回密码或管理链接。

### 10.2 反馈按钮

`ImageComparison` 在检测任务和检测历史两个页面共用。在结果卡片标题栏右侧、图片序号与翻页按钮左侧增加“结果反馈”按钮。

- 图片处理完成后按钮可用。
- 处理中或处理失败时按钮禁用，不打开空弹窗。
- 按钮同时出现在当前任务结果和历史预览中。
- 点击时再读取当前用户反馈；已有反馈时回填弹窗，提交后更新本地状态。

### 10.3 反馈弹窗

弹窗显示当前文件名和图片序号，包含两个区域：

1. **已检测区域**
   - 每个实际检测框单独一行。
   - 显示逻辑区域名、模型原始标签和模型当前分类结果，模型结果只读。
   - 首次提交时不自动选中模型结果，用户必须明确选择 `OK` 或 `NG`。
   - `label1_thin` 和 `label1_thick` 在逻辑名上统一显示为 `label1`，同时显示实际变体，并必须选择 `B/G/R/W` 颜色。
2. **漏检区域**
   - 只显示当前未检测到的逻辑区域。
   - 使用多选控件让用户确认真实漏检项。
   - 漏检项不显示 `OK/NG` 或颜色选择。

所有实际检测框填写完成前禁止提交。图片无任何检测框时，至少选择一个漏检区域才能提交。提交期间防止重复点击，保存成功后关闭弹窗并显示“反馈已保存”；失败时保留已填内容并就地显示错误。

## 11. 配置与部署

- Python 依赖增加 Argon2id 密码哈希库，同步更新 `requirements.txt`、`pyproject.toml` 和 `uv.lock`。
- `SESSION_TTL_HOURS` 默认为 `12`。
- `SESSION_COOKIE_SECURE` 默认为 `false`，由 `.env`、原生启动和 Compose 环境共同传递。
- Alembic 新增一个迁移，创建五张表、唯一约束、索引和外键。旧任务、图片和检测结果无需回填。
- `deploy.sh` 和原生一键启动流程继续自动执行 Alembic 迁移，但不自动生成默认用户或密码。
- 升级后管理员必须通过 `manage_users.py add` 创建首个用户，网页才能登录。

## 12. 迁移、兼容性与回滚

- 迁移只新增表和索引，不修改现有推理数据。
- 升级后 API 立即要求登录，新前端与新后端必须作为同一版本部署。
- 降级迁移删除反馈、会话和用户表，因而会丢失人工反馈和账户数据；生产回滚前必须使用现有 `pg_dump` 备份。
- 直接从数据库删除用户受反馈外键限制；使用 `disable` 保留反馈归属，不应删除已提交反馈的用户。

## 13. 错误处理

- 登录错误不泄露账户是否存在或是否被禁用。
- 会话失效不清空页面历史数据，但前端必须停止继续请求受保护接口并进入登录页。
- 打开反馈弹窗失败时在弹窗内显示加载错误和重试操作，不卸载历史列表或当前预览。
- 提交反馈失败时保留用户输入，禁止重复提交期间产生并发写入。
- 反馈验证错误返回可读的字段级原因，后端仍作为最终约束边界。
- 已有反馈任务的删除请求返回稳定的 HTTP `409` 错误文案，前端不将其显示为数据库故障。

## 14. 测试与验收

### 14.1 后端

- 用户名严格区分大小写，密码数据库值为 Argon2id 哈希而非明文。
- 登录成功、密码错误、不存在用户、禁用用户、退出、12 小时过期和会话撤销。
- 公开健康检查与所有受保护路由的 `401` 边界。
- 反馈创建、同用户更新、不同用户互不覆盖和当前用户反馈回读。
- 检测 ID 缺少、重复、跨图片、非法判定、label1 缺颜色、其他区域多颜色和空反馈均被拒绝。
- `label1_thin`/`label1_thick` 逻辑映射和漏检候选集计算。
- 已检测区域不能标记漏检，未检测区域可由用户选择。
- 图片未完成、图片失败和无效图片 ID 的错误。
- 已有反馈任务禁止删除，无反馈任务保持现有删除行为。
- Alembic 升级、降级及 PostgreSQL 外键和唯一约束。
- 用户管理命令的新增、列表、重置密码、禁用和启用路径。

### 14.2 前端

- 应用启动认证检查、登录成功、登录失败、目标路由恢复、退出和会话过期跳转。
- 登录页不存在注册和找回密码入口。
- 当前任务和历史预览均显示反馈按钮，处理中和失败图片不能反馈。
- 反馈弹窗加载、回填、`OK/NG` 必填、label1 颜色必填、漏检多选和空反馈校验。
- 提交成功、提交失败保留输入、防重复提交和关闭弹窗。
- `hasFeedback=true` 的任务禁用删除操作并显示保留原因。
