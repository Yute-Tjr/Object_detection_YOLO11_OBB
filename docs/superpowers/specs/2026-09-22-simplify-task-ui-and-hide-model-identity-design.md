# 检测任务界面简化与模型身份隐藏设计

日期：2026-09-22

## 1. 背景与目标

当前“检测任务”页面同时承担任务创建、当前任务结果展示和历史任务浏览，页面底部重复展示了“检测历史”页面已有的任务表。任务创建还要求填写操作员，并允许填写任务名称和备注，但这些元数据不再属于生产检测流程的必要信息。页面和公开 API 还会显示或返回模型名称、版本及校验值。

本次调整的目标是：

1. “检测任务”页面只保留图片上传、开始检测、当前任务进度和当前任务结果。
2. 历史任务只能在“检测历史”页面浏览、预览和删除。
3. 永久删除任务的操作员、任务名称和备注字段及其历史数据。
4. 网页及其公开 API 不再显示或返回具体模型身份。
5. 保留服务内部模型注册、模型加载和任务执行所需的数据，不影响推理流程。

## 2. 非目标

- 不删除 `model_registry` 表、模型权重配置或 Worker 内部模型注册逻辑。
- 不删除任务 ID、图片、检测结果、任务状态和创建时间。
- 不改变目标检测、异常分类、结果渲染和历史文件持久化流程。
- 不改变删除任务功能及其站内确认卡片的安全保护。

## 3. 页面设计

### 3.1 检测任务页面

页面保留以下内容：

- 通用系统状态：“正在检查系统”“系统已就绪”或“系统未就绪”。
- 图片拖拽与选择区域。
- 已选择图片数量、图片移除与清空操作。
- “开始检测”按钮。
- 当前任务进度、处理阶段和当前任务 ID。
- 当前任务的检测前后对比结果。

页面删除以下内容：

- 操作员、任务名称和备注输入区。
- “当前模型”文本。
- 进度面板中的模型名称。
- 页面底部历史任务表及其加载请求、选择逻辑和本地状态。

开始检测按钮只由以下条件控制：已选择至少一张图片、不超过 100 张、服务整体就绪且当前没有正在提交的创建请求。

### 3.2 检测历史页面

历史页面继续负责全部任务的筛选、搜索、预览和删除。任务表进行以下调整：

- 删除“模型”列。
- 删除展开按钮和任务详情行。
- 删除不再有用途的 `TaskDetails` 组件。
- 保留任务 ID、图片数量、完成进度、当前阶段、状态、创建时间和操作列。
- 删除确认卡片只显示任务 ID、图像数量和不可恢复提示，不再显示任务名称。

搜索改为由后端统一执行，只搜索任务 ID 和原始图片文件名。前端不再对后端结果按已删除字段进行二次过滤，避免图片文件名命中的结果被错误隐藏。搜索提示改为“搜索任务 ID 或图片文件名”。

## 4. 数据库设计

新增 Alembic 迁移，在 `inspection_tasks` 表中永久删除：

- `operator`
- `name`
- `note`

升级迁移会删除现有三列中的历史值，无法恢复。降级迁移仅能重新创建三个可空列，不能恢复被删除的数据。部署脚本现有的 `alembic upgrade head` 会自动执行该迁移。

任务内部的 `detector_model_id` 保留。它属于服务内部推理和模型注册关系，不通过任务公开响应返回。

## 5. 后端接口与内部边界

### 5.1 创建任务

`POST /api/v1/tasks` 只接收图片文件，不再接收或校验操作员、任务名称和备注。仓储层创建任务的方法同步移除这些参数。

### 5.2 任务响应

任务摘要和任务详情响应删除：

- `operator`
- `name`
- `note`
- `detectorModel`

任务内部仍可关联检测模型记录，但 presenter 不再读取和序列化模型名称。

### 5.3 健康检查

`GET /api/v1/health` 的公开响应只返回：

- `apiReady`
- `databaseReady`
- `workerReady`
- `modelsReady`

删除公开响应中的 `models` 数组，因此浏览器无法获得模型名称、版本、哈希或模型错误详情。内部 readiness 状态文件和 Worker 日志可以继续保存模型加载细节，便于服务端诊断。

### 5.4 分类结果

分类结果公开响应删除 `modelName` 和 `modelVersion`。分类类型、预测标签、置信度和概率保持不变。

### 5.5 搜索

任务查询删除对 `InspectionTask.name` 的依赖，只匹配：

- 任务展示 ID。
- 关联图片的原始文件名。

## 6. 前端类型与数据流

- `CreateTaskMetadata` 类型删除，`createTask` 改为只接收图片列表和可选取消信号。
- `TaskSummary` 删除三个任务元数据字段和 `detectorModel`。
- `HealthResponse` 删除模型明细数组；页面只消费整体 readiness 布尔值。
- `ClassificationResult` 删除模型名称和版本。
- `UploadPanel` 删除元数据 props 和相关状态。
- `ImageComparison` 不再根据模型清单判断颜色能力；当前继续显示已有的“颜色分类：接口预留”文案。

## 7. 错误处理与兼容性

- 数据库迁移必须先于新版 API 服务启动，由现有部署流程保证。
- 新前端与旧后端、新后端与旧前端的数据契约不再完全兼容，因此 API、Worker 和前端必须作为同一版本一起部署。
- 服务未就绪时只显示通用提示，不向用户展示具体模型文件名或模型错误；详细原因保留在 API/Worker 服务端日志中。
- 历史任务的图片、状态和检测结果不依赖被删除字段，迁移后仍可正常预览和删除。

## 8. 测试与验收

后端测试覆盖：

- 不带元数据即可创建任务。
- 创建任务接口不再要求、使用或返回旧字段。
- 任务、健康检查和分类响应不包含模型身份。
- 搜索任务 ID和图片文件名仍有效。
- Alembic 升级后列被删除，降级后只恢复空列。
- 原有任务处理、预览和删除测试继续通过。

前端测试覆盖：

- 检测任务页面不存在元数据输入、模型名称和历史任务表。
- 选择图片后可直接创建任务。
- 健康状态使用通用文案。
- 历史任务表不存在模型列和展开详情。
- 删除确认卡片不显示任务名称。
- 历史搜索仍正确调用后端。

最终验收要求：Python 全量测试、前端全量测试、TypeScript 类型检查、Vite 生产构建和 Alembic 迁移检查全部通过。
